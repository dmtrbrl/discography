# Artist and booklet source handoff

Research checked 2026-10-28. This is a source list for the data-fetching module, not a record of assets already downloaded into the app.

## Acceptance rule

An artist qualifies when **at least one official CD release** has an **available scan showing something inside its booklet or insert**, and the artist's music is listed in Apple's music catalog. A cover and back insert alone are a no-go. One genuine interior page or spread is enough; a long booklet is a bonus, not a requirement. The early 1990s through early 2000s and indie/pop/electronic preferences are useful for choosing albums, but are not hard exclusions (Rammstein and the later Crystal Castles albums were specifically discussed).

Apply the rule **per CD pressing**. A `Booklet` tag alone is not proof of an interior: inspect the image, since it might be the cover or the booklet's back. Archived image counts are scan counts, not necessarily page counts; an image may be a two-page spread or a fully opened foldout. Confirm that the image actually downloads before marking an album ready.

## Fetching and asset recommendations

1. **Pin the exact MusicBrainz release ID** for every chosen album. A release group identifies an album across many pressings; it does not identify the booklet scan sequence. Prefer front, back, CD and booklet from the same release when the archive supplies them. If artwork must come from different pressings, record that in provenance and visually check that the combination is coherent.
2. Query the [Cover Art Archive release endpoint](https://coverartarchive.org/) (`https://coverartarchive.org/release/{release-id}`) and inspect each image's `types`, `comment`, `id`, `image` and `thumbnails` fields. `Booklet`, `Panel`, and occasionally untyped images need visual classification. Exclude the jewel-case back insert, tray, disc, matrix and obi from booklet pages.
3. **Download and inspect at least one real interior image before accepting an album.** Retry transient MusicBrainz/Cover Art Archive failures, but keep the album pending if the actual image cannot be retrieved. A `Booklet` label without an accessible interior is insufficient. Keep a provenance manifest of release ID, image ID, role, source URL, page/spread order and any crop instructions.
4. Normalize each booklet to ordered square pages for [LeafThrough](https://github.com/dmtrbrl/leafthrough). Split two-page spreads, orient both sides of foldouts correctly, and separate multiple inserts. Preserve the original scan files as sources so crops can be corrected. The app's planned `spread` layout is described in [`ROADMAP.md`](ROADMAP.md#phase-2a-booklet-as-a-flip-book).
5. The existing [`scripts/download-covers.sh`](scripts/download-covers.sh) fetches a cover, disc, back insert and **only one** manually chosen booklet-back image. Its automatic earliest-CD selection does not guarantee the verified booklet pressing. Extend or replace that logic for ordered booklet pages; do not assume the existing `bookletBack` value is the entire booklet.
6. At fetch time, use the iTunes Search API with storefront `AT` for the intended album and tracks if previews are needed. Match artist, album and release carefully; do not assume an Apple Music listing guarantees a purchasable iTunes album or a non-null `previewUrl`. Save missing-preview status rather than substituting an unrelated track.

The qualifying artist list is a source-selection recommendation. Only Nirvana is currently implemented in the app; adding the four other artist datasets and the flipbook images is future work.
